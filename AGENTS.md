## Проект

**Amicus** (рабочее название было «Круг») — мобильная соцсеть, где лента
показывает посты только тех, с кем есть подтверждённое «знакомство»
(Connection): через одноразовую invite-ссылку или QR при личной встрече.
«Комнаты» (Room) — часть общей идеи, но отложены за пределы MVP.

Проект пилотный/портфолио: автор — новичок в мобильной разработке, но с опытом
SQL/PostgreSQL и C#/.NET. Работать пошагово по этапам, не забегая вперёд — это
осознанное решение, а не отсутствие плана.

## Статус

MVP задеплоен на Android (Google Play, Internal Testing). Текущая версия —
`0.13.0+26`. Есть: вход/регистрация, профиль с аватаром и списком своих постов,
знакомства через invite-коды, лента с постами (текст + одно фото), реакциями и
комментариями с одноуровневой вложенностью, mute/блокировка, избранное,
push-уведомления о постах, две локали, тёмная тема.

iOS отложена целиком (нужен Xcode). Дальнейшая работа — по future-development.md.

## Стек

Flutter/Dart + Supabase (PostgreSQL, Auth, Storage, RLS). Riverpod, go_router,
`flutter_localizations` + ARB. На будущее (не сейчас) рассматривался свой
backend на ASP.NET Core.

## Ограничения среды

- **macOS 12.7.6.** Flutter новее 3.32.8 не запускается (нужна macOS 14+), SDK
  закреплён на 3.32.8. Не предлагать обновление — это тупик.
- **Только Android.** Xcode тоже требует более новую macOS.
- `compileSdk`/`targetSdk` прибиты числом **36** в `android/app/build.gradle.kts`
  (требование Play), AGP **8.9.3** на Gradle **8.12** — более новый AGP потребует
  Gradle 8.13.
- Запуск: `flutter run --dart-define-from-file=.env` из `app/`. `.env` не в
  репозитории, шаблон — `app/.env.example`.

## Конвенции работы

- **Миграции применяются вручную** через Supabase Management API
  (`POST /v1/projects/<ref>/database/query`). CI **не** делает `supabase db push`.
  Токен даёт пользователь на время задачи, в репозиторий и в память не пишется.
  После применения — дописать строку в `supabase_migrations.schema_migrations`,
  иначе будущий `db push` накатит миграцию повторно.
- **RLS проверять симуляцией**, а не на глаз: `begin; set local role authenticated;
  select set_config('request.jwt.claims','{"sub":"<uuid>"}',true); … rollback;`.
  Management API работает суперпользователем и RLS не применяет. Сначала
  воспроизвести дыру, потом закрыть, потом сверить контрольные числа до/после.
- **Версия бампается в каждом PR**: `make verify-version BASE_REF=origin/main`,
  формат `name+build`.
- **Перед сдачей**: `make verify` (deps, формат, analyze, тесты).
- **Локализация**: строки в `app/lib/l10n/app_{en,ru}.arb`, генерация —
  `flutter gen-l10n`, сгенерированные файлы коммитятся. Править ARB **текстом**:
  переписывание через `json.dump` съедает пустые строки, которыми файл разбит на
  смысловые группы.
- **CLAUDE.md — побайтовый близнец этого файла** (отличаются только заголовок и
  «для Codex»/«для Claude»). Менять оба.

## Схема и правило видимости

Таблицы: `users`, `connections`, `invite_links`, `posts`, `reactions`,
`comments`, `muted_users`, `blocked_users`.

**Одно правило видимости на весь проект** — `is_author_visible(uuid)`: я сам,
либо Connection, которого я не замьютил и с которым нет блока ни в одну сторону.
Его спрашивают SELECT-политика `posts`, `reaction_summary()`, обе политики
`comments` (через `is_author_of_comment_visible()`) и storage-политика на фото
постов. **Менять только в этой функции.** Раньше правило было размножено на
четыре копии, две отстали от mute/block и стали дырами — см. 0.11.0 в CHANGELOG.

В политиках оно используется как `author_id in (select visible_author_ids())`, а
не как построчный вызов — см. «Грабли».

Комментарии: вложенность **ровно одноуровневая**. `parent_comment_id` — корень
ветки, `reply_to_id` — адресат (только для метки «в ответ»), `deleted_at` —
заглушка. Удаление идёт через RPC `delete_own_comment()`: с ответами —
заглушка, без — реальный delete, решает сервер. DELETE- и UPDATE-политик на
`comments` намеренно нет: редактирование комментариев — не фича.

Серверные колонки прибиты в INSERT-политиках `posts`/`comments`:
`created_at = now()`, `deleted_at is null`.

`activate_invite_link()` кидает стабильные SQLSTATE — `PT404` (не найден),
`PT409` (использован), `PT422` (свой собственный); клиент мапит их в строки из
ARB и никогда не показывает `e.message`.

Storage: бакет `media` приватный, signed URL живут 24 ч. `posts/<uid>/…` — по
`is_author_visible`. `avatars/<uid>/…` — себе и Connections, **блок их не
сужает**: заблокированный остаётся в списке знакомых и на экране
«Заблокированные», где блок и снимают, а оба экрана рисуют аватарку.

## Грабли

- **RLS применяется и к подзапросам внутри политики.** Подзапрос к
  `blocked_users` сам фильтруется политикой `blocked_users`, поэтому ветка «меня
  заблокировали» молча отваливалась. Отсюда весь паттерн `security definer` +
  `set search_path`. Это самая нагруженная мысль во всей схеме.
- **`security definer`-функцию планировщик не инлайнит.** Не ставить её
  построчным фильтром в `using`, если она зависит только от `auth.uid()` —
  поднимать в некоррелированный `IN (SELECT …)`, он хэшируется один раз. Разница
  на ленте была 217 мс → 3.5 мс.
- **Каждая функция в `public` — эндпоинт PostgREST.** Выдавать
  `grant execute … to authenticated` только если каждый аргумент про самого
  вызывающего; иначе она отвечает на чужие вопросы.
- **Дефолтные гранты Supabase дают `authenticated` писать все колонки.** Любая
  новая колонка, которую заполняет сервер, должна быть явно упомянута в
  INSERT-политике.
- **У `order()` в postgrest-dart дефолт `ascending: false`.** Стоило реального
  бага с перевёрнутыми ветками.
- **`timestamptz` из PostgREST парсится как UTC.** Конвертировать
  `parseTimestamp()` на границе «строка → модель», а не в местах отображения.
- **У сетевых запросов нет клиентского таймаута** — офлайн-отправка висит со
  спиннером минуты. Ветка ошибки корректна, но пользователь этого не видит.
- **Жест «назад» нельзя проверять на экранах через `context.go()`** — он
  заменяет маршрут, стек пуст, и сворачивание приложения законно на любой версии
  Android. Проверять только `Navigator.push()`-экраны. Отмену жеста через `adb`
  достоверно проверить нельзя — вердикт выносит система, а инъецированные
  события идут без скорости.
- **Проверка на устройстве**: английскую локаль включать пер-приложенчески
  (`adb shell cmd locale set-app-locales <pkg> --locales en-US`), а не системной
  настройкой — не трогает телефон пользователя и откатывается пустым значением.

## Границы MVP и что дальше

MVP (0.1) — регистрация/вход, профиль, invite-ссылки → Connection, общая лента,
реакции, комментарии. Отложено: комнаты целиком, QR-сканирование,
push-уведомления о комментариях/реакциях (push о постах уже есть, см.
CHANGELOG 0.12.0), модерация/жалобы, web-версия, свой backend, iOS.

Нерешённые вопросы (кто добавляет в комнату, судьба комнаты при удалении
создателя, разрыв Connection, приватность списка контактов) — в
future-development.md. Решать по мере того, как доходит очередь, не заранее.
